# Подключение API: инструкция администратору

Актуально для версии с официальным входом Google и соцсетей, 18 сентября 2026.

Новый Google OAuth пока не подтверждён подключением реального аккаунта. Настройка
приложения, допуск тестировщиков и успешный вход — отдельные этапы. Ранее сохранённые
YouTube API-ключи продолжают поддерживаться; массовая замена ключей не требуется.

  Access. В Branding сохранены название «Контент-завод», контакты поддержки и

  `YOUTUBE_CLIENT_SECRET` и `YOUTUBE_OAUTH_ENABLED=true` импортированы на VPS;
  app и sync перезапущены.
- **Instagram / Threads:** callback-адреса на порту 21443 сохранены в Meta.
  Получение App Secret требует повторного ввода пароля Facebook; этот этап
  не завершён. **TikTok:** вход в кабинет не выполнен. **VK:** работа с кабинетом

- По просьбе пользователя реальный OAuth-вход и сбор статистики **не проверялись**.
  Сохранение настроек и перезапуск сервисов не доказывают успешное подключение
  аккаунта, обновление токенов или получение показателей.

## С чего начать, если показатели не заполняются

Сначала откройте «Доступы соцсетей» в админке и проверьте готовность приложений.
Отсутствующий App ID / App Secret или выключенный OAuth — задача администратора,
креатор не исправит её повторной отправкой ссылки или поиском API в настройках
своего аккаунта. Приложение также должно иметь разрешение площадки на работу
с внешними пользователями; заполненные переменные сами по себе этого не доказывают.

Порядок запуска:

1. Настройте необходимые приложения по разделам ниже и внесите серверные секреты.
2. Пройдите вход каждым разрешённым тестовым аккаунтом и дождитесь первой
   успешной проверки; проверьте все доступные показатели, дату и источник.
3. Убедитесь, что production-доступ одобрен для внешних креаторов.
4. Пользователь проходит: роль → ИИ/UGC → «Добавить канал» → соцсеть → ссылка →
   подключение → показатели. Креатор может начать без приглашения. У продюсера
   свои каналы и команда разделены; обходить все шесть площадок не требуется.
5. Если в карточке «недоступно», под ней должен быть следующий шаг и кнопка
   «Инструкция файлом». Разделяйте отсутствие доступа, временную ошибку и
   документированное ограничение источника: для RuTube лайки этот источник не выдаёт,
   VK не гарантирует полный охват Клипов. Не обещайте заполнить их новым токеном.

### Файлы для креаторов

В Telegram общий TXT отправляется через `/help` → «Инструкция файлом», файл
площадки — из карточки → «Помощь» → «Инструкция файлом». Это настоящий документ Telegram,
его можно сохранить и переслать; он не содержит персональных ссылок или секретов.
Копии в репозитории: `docs/creator-guides/`. Чтобы обновить их после правки текста:

```sh
node scripts/export-social-guides.mjs
```

Источник текста единый: `lib/social-instructions.mjs` и
`lib/social-guide-files.mjs`. Каждый файл содержит весь маршрут, ожидаемый результат,
пример карточки, действия при ошибке, ограничения и официальные ссылки.

Креаторам не нужно создавать приложения и передавать пароли. Вы один раз
регистрируете приложения сервиса и настраиваете сервер. Затем каждый креатор
в боте открывает свой канал → «Подключить API» → официальный вход в соцсеть.
Платформа получает токены, проверяет аккаунт, шифрует доступ и запускает сбор.
Для YouTube основной путь: «Подключить YouTube» → «Войти через Google» →
персональная страница → «Войти через Google». Пользователь разрешает чтение
`youtube.readonly`; собственный проект или новый API-ключ создавать не нужно.
Сохранённые API-ключи остаются совместимыми. Этот путь одинаков для собственных
каналов креатора и продюсера. RuTube собирается по публичной ссылке без входа.

Личный доступ подтверждает **сам владелец канала** из своего Telegram.
Продюсер не собирает и не загружает их ключи. Серверные App ID / App Secret ниже —
настройка приложения сервиса, а не личный API-доступ креатора.
В боте `/guide` открывает следующий шаг по добавленному каналу; `/api` — свои подключения.
До 10 ссылок в сообщении: каждый результат независим, повтор не создаёт дубли.

## Threads (новая площадка)

1. В Meta for Developers добавьте к приложению продукт / use case Threads API.
   Используйте именно Threads App ID и Threads App Secret, не Instagram App ID.
2. Добавьте точный callback:
   `https://kontent-zavod.217-60-183-146.sslip.io:21443/connect/oauth/threads/callback`
3. Требуются `threads_basic` и `threads_manage_insights`. Для внешних креаторов
   получите требуемое Meta одобрение/Advanced Access; тестовые роли не заменяют review.
4. В конфигураторе выберите `threads`: задайте `THREADS_CLIENT_ID` и
   `THREADS_CLIENT_SECRET`. `THREADS_OAUTH_ENABLED=true` — только после настройки
   и разрешения площадки. Перезапустите app и sync, не меняя бот-токен и пароль.
5. Креатор отправляет `threads.com/@имя` или `threads.net/@имя` (также поддерживается
   `/@имя/post/код`), затем сам нажимает `/api` → канал → официальный вход Threads.
   Ключи приходят автоматически, пересылать их продюсеру не требуется.
6. Проверьте пустой профиль, профиль с текстом/каруселью/видео, отказ в статистике
   и повторное подключение. Подключение должно соответствовать username канала.

Токен меняется на long-lived и продлевается после 24 часов. Готовый long-lived
Threads-токен можно импортировать самим креатором через персональную форму после
24 часов, когда можно проверить refresh. Instagram-токен не подходит.
Считаются основные собственные посты и их lifetime views/likes; репосты, ответы
и ghost posts исключаются. Просмотры профиля из user insights не подменяют просмотры
постов. Карусель — одна публикация. Данные по отдельным постам не сохраняются в БД.

Официальные источники:
[OAuth и токены](https://developers.facebook.com/documentation/threads/get-started/get-access-tokens-and-permissions/),
[посты](https://developers.facebook.com/documentation/threads/retrieve-and-discover-posts/retrieve-posts/),
[статистика](https://developers.facebook.com/documentation/threads/insights/).

Регистрация приложения, заполнение настроек и одобрение площадки — разные этапы.
Развёртывание кода не означает получение разрешений. Не включайте массовый
доступ до одобрения и проверки реальным аккаунтом. Тестовые режимы используйте
только для разрешённых площадкой тестировщиков.

## 2. Instagram / Meta

1. В Meta for Developers зарегистрируйте приложение для бизнеса и добавьте
   Instagram API with Instagram Login. Для этого пути Facebook Page не обязательна.
2. В настройках Instagram API возьмите **Instagram App ID и Instagram App Secret**,
   не идентификаторы другого продукта Meta.
3. Зарегистрируйте точный Redirect URI из админки:
   `https://kontent-zavod.217-60-183-146.sslip.io:21443/connect/oauth/instagram/callback`
4. Запросите `instagram_business_basic` и `instagram_business_manage_insights`.
   Для сторонних креаторов нужны App Review/Advanced Access. Не используйте
   массовую выдачу ролей тестировщиков вместо одобрения.
5. Укажите публичные страницы конфиденциальности и удаления данных; подготовьте
   демонстрацию добавления канала, входа и просмотра агрегированной статистики.
6. На сервере запустите конфигуратор ниже для `instagram`. Он запросит
   `INSTAGRAM_CLIENT_ID`, `INSTAGRAM_CLIENT_SECRET` и явное включение входа.
7. После перезапуска протестируйте профессиональный аккаунт «Автор»/«Бизнес»:
   бот → канал → вход → разрешения → успех → первый сбор. Личный аккаунт не подходит.

Код автоматически меняет краткосрочный токен на долгоживущий и продлевает его.
При отзыве разрешений креатор повторяет вход. Ручной ввод принимает только
долгоживущий токен, для которого уже разрешено продление (возраст от суток).
Фото, карусели и Stories не входят в число видео; часть старых/скрытых insights
может быть недоступна. Просмотры — не уникальный охват.

Источники: [Business Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/business-login/),
[Insights](https://developers.facebook.com/documentation/instagram-platform/insights/),
[App Review](https://developers.facebook.com/documentation/instagram-platform/app-review).

## 3. TikTok

1. Создайте приложение в TikTok for Developers. Выберите Web, подключите Login
   Kit и Display API. Sandbox и production — разные режимы.
2. Укажите публичный URL сервиса, Privacy Policy и Terms. Выполните проверку
   владения URL/доменом способом, предложенным TikTok.
3. Добавьте статический HTTPS Redirect URI без query и завершающего слеша:
   `https://kontent-zavod.217-60-183-146.sslip.io:21443/connect/oauth/tiktok/callback`
4. Запросите `user.info.basic`, `user.info.profile`, `user.info.stats`, `video.list`.
5. Подготовьте video demo всех запрошенных прав и отправьте приложение на review.
   Не включайте production-вход до разрешения. При тестировании добавьте только
   разрешённых тестовых пользователей в Sandbox.
6. Конфигуратор `tiktok` запросит `TIKTOK_CLIENT_KEY` и `TIKTOK_CLIENT_SECRET`.
   Серверные секреты не выдаются креаторам и не вставляются в бот.
7. Пройдите полный вход аккаунтом с опубликованными видео и проверьте все три
   показателя. Отказ от `video.list` должен завершиться понятной ошибкой, а не
   заменить рабочий доступ.

Пара access/refresh получается автоматически. Access обычно действует сутки;
новый refresh token сохраняется при ротации до запросов статистики. Не импортируйте
токены из другого приложения: продление требует совпадения client key/secret.

Источники: [Login Kit Web](https://developers.tiktok.com/docs/en/login-kit-web),
[Display API](https://developers.tiktok.com/docs/en/display-api-get-started),
[review](https://developers.tiktok.com/docs/en/app-review-guidelines).

## 4. VK ID / VK Видео

1. Зарегистрируйте приложение VK ID в кабинете бизнеса; выполните необходимые
   требования к подтверждению бизнес-профиля.
2. Для этого серверного подключения выберите **confidential** приложение.
   Добавьте исходящий IP сервера `217.60.183.146` в разрешённые IP приложения.
3. Укажите Base domain и доверенный Redirect URI:
   `https://kontent-zavod.217-60-183-146.sslip.io:21443/connect/oauth/vk/callback`
   Домен должен совпадать. Если кабинет не принимает нестандартный порт,
   сначала настройте собственный домен с HTTPS:443, не подменяйте callback.
4. Отдельно согласуйте право `video` с VK: `devsupport@corp.vk.com`.
   По документации оно предоставляется в исключительных случаях. Регистрация
   VK ID сама по себе не даёт доступ к `video.get`.
5. Конфигуратор `vk` запросит `VK_CLIENT_ID` и `VK_SERVICE_TOKEN` (сервисный токен
   confidential-приложения). Он используется на сервере для code exchange и refresh.
   Это НЕ ключ сообщества для чтения видео и НЕ пользовательский access token.
6. После разрешения и перезапуска креатор входит через VK ID. Access, refresh,
   device ID и client ID заполняются автоматически. Для сообщества нужен вход
   пользователя, который им управляет.

Проверяются владелец профиля или права администратора сообщества и доступ `video`.
Считаются собственные доступные видео. Полнота отдельного раздела «Клипы»
не гарантируется методом `video.get`; это ограничение отражается в статусе.

Источники: [VK ID Web](https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/web/auth-without-sdk),
[confidential app](https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/create-application),
[video.get](https://dev.vk.ru/ru/method/video.get).

## 5. YouTube / Google OAuth

Основной путь — официальный вход Google с разрешением только
`https://www.googleapis.com/auth/youtube.readonly`. Пользователь не создаёт
собственный OAuth-клиент и не покупает API-ключ. Настройка проекта приложения
выполняется администратором один раз; действуют квоты YouTube Data API.

1. В проекте сервиса Google Cloud через APIs & Services → Library включите
   YouTube Data API v3. Используйте этот же проект для OAuth-клиента.
2. В Google Auth Platform заполните Branding: название приложения, контакты,
   разрешённые домены и публичные ссылки продукта, конфиденциальности и условий.
   Указывайте реальные сведения оператора. Домен и точный redirect URI должны
   приниматься Google; если текущий `sslip.io:21443` не принимается, нужен свой
   подтверждённый домен с HTTPS. Не подменяйте callback похожим адресом.
3. В Audience выберите режим для нужной аудитории. Для первой проверки External /
   Testing добавьте конкретные разрешённые Google-аккаунты в Test users. Аккаунт
   должен управлять нужным YouTube-каналом; для Brand Account допустим тестировщик,
   который им управляет. Testing — не массовый production-доступ: в этом режиме
   разрешение и refresh token истекают через 7 дней. Для постоянной работы проверьте
   требования Google к публикации и verification; у организаций возможны свои ограничения.
4. В Data Access добавьте только `youtube.readonly`. Права загрузки, изменения и
   удаления видео для сбора не требуются. В Clients создайте OAuth client типа
   Web application. Зарегистрируйте точный Authorized redirect URI:
   `https://kontent-zavod.217-60-183-146.sslip.io:21443/connect/oauth/youtube/callback`.
   При смене `CONTENT_PUBLIC_ORIGIN` синхронно меняются адрес приложения и callback.
5. Через `configure-api.py youtube` внесите `YOUTUBE_CLIENT_ID` и
   `YOUTUBE_CLIENT_SECRET`. Включайте `YOUTUBE_OAUTH_ENABLED=true` после настройки
   разрешённого тестового режима или production. Секрет принадлежит приложению,
   пользователю и в Telegram его не передают. Сохраните `SOCIAL_VAULT_KEY`.
6. Пользователь: «Мои каналы» → нужный канал → «Подключить YouTube» →
   «Войти через Google» → персональная страница → «Войти через Google».
   Он выбирает Google-аккаунт и нужный канал/Brand Account, читает разрешение
   и завершает вход в том же браузере. Неверный канал должен дать понятный отказ
   и сохранить прежнее рабочее подключение.
7. После подтверждения проверьте в боте реальные показатели и время обновления.
   Для приостановленного канала сначала «Возобновить сбор». Проверьте пустой канал,
   непустой публичный каталог, отказ от разрешения, неверный канал, отмену,
   истечение формы и повторный сбор после обновления токена. Успешный callback
   сам по себе не доказывает, что метрики собраны.

Сервер использует OAuth code exchange с PKCE и запрашивает offline-доступ для
обновления access token. Токены хранятся за владельцем и выбранным каналом;
повторный вход нужен при отзыве/истечении доступа. Отчёт продолжает считать
доступные публичные видео и не обещает полную аналитику YouTube Studio.

Старые сохранённые API-ключи остаются рабочим альтернативным типом подключения;
их не требуется удалять или менять при выпуске OAuth. Общий серверный ключ
не подменяет личное подключение. Если старый ключ перестал работать, проверьте
YouTube Data API v3 в его проекте и ограничения API/IP `217.60.183.146`; новый
рекомендуемый способ подключения пользователя — официальный Google-вход.

и пустого публичного канала. Она не подтверждает Google OAuth, сбор непустого
каталога или обновление доступа через сутки. Новый путь на 18 сентября требует
отдельной проверки реального входа. Актуальная инструкция пользователя:
`docs/YOUTUBE-QUICK-START.txt`.

При прежнем подключении исправлена серверная причина отказа корректного ключа:
workerd не поддерживает `fetch` с `redirect: 'error'`. Адаптеры используют
`redirect: 'manual'` и отклоняют 3xx, не переходя по Location. Такое ограничение
сервера не исправляется созданием новых ключей пользователем.

Источники: [OAuth для YouTube](https://developers.google.com/youtube/v3/guides/authentication),
[серверный вход и offline-доступ](https://developers.google.com/youtube/v3/guides/auth/server-side-web-apps),
[Testing и аудитория приложения](https://support.google.com/cloud/answer/15549945),
[разрешения Google](https://developers.google.com/identity/protocols/oauth2/scopes#youtube).

## 6. RuTube

Ничего настраивать не нужно. Креатор добавляет публичный канал. Текущий источник
возвращает ролики и просмотры, но не лайки. Не просите у людей несуществующий
«ключ RuTube для лайков» и не заменяйте недоступные показатели нулями.

## 7. Безопасная настройка сервера

Через SSH на VPS, без отправки секретов в переписку:

```sh
python3 /opt/kontent-zavod/current/deploy/vps/configure-api.py instagram
python3 /opt/kontent-zavod/current/deploy/vps/configure-api.py threads
python3 /opt/kontent-zavod/current/deploy/vps/configure-api.py tiktok
python3 /opt/kontent-zavod/current/deploy/vps/configure-api.py vk
```

Запускайте только команды нужных площадок. Поля скрыты при вводе. Пустой ввод
сохраняет существующее значение; отсутствующее обязательное поле отменяет запись.
Скрипт сохраняет резервную копию, не меняет пароль root, вход в админку, токен
Telegram-бота или `SOCIAL_VAULT_KEY`. Без явного `YES` официальный вход площадки
остаётся выключенным. Не передавайте значения аргументами командной строки.

После настройки:

```sh
systemctl restart kontent-zavod.service kontent-zavod-sync.service
systemctl is-active kontent-zavod.service kontent-zavod-sync.service kontent-zavod-telegram.service
```

Откройте «Доступы соцсетей», проверьте готовность, затем подключите разрешённый
реальный аккаунт через бот. Сам факт запущенной службы не доказывает работу API.

## 8. Приёмка перед рассылкой

- Новый креатор появился в общей админке вместе с Telegram продюсера.
- Выбор ИИ/UGC сохранён; ссылки на каналы не задублированы.
- OAuth правильного аккаунта успешен; чужой аккаунт, отказ от прав и отмена
  не меняют прежнее рабочее подключение.
- Повторное открытие страницы результата не обменивает код повторно.
- Удаление/отключение канала аннулирует его незавершённые подключения.
- Первый сбор действительно получил разрешённые показатели; проверены время,
  источник, полный каталог и следующий срок. Проверить повтор спустя сутки.
- В админке, выгрузке и логах нет access/refresh/client secret.
- Публичны только гайды, страницы продукта и точные OAuth-маршруты. `/api/data`
  требует прежние креды, `/api/telegram` и `/api/sync` извне закрыты.

Креаторам отправляйте ссылку `/api-guide`, не этот технический документ и не ключи приложений.
